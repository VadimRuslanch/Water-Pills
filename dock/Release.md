
# План 2. Как разрабатывать приложение

Главный принцип:

**не делать сразу все экраны.**

Сначала делаем одну законченную пользовательскую цепочку.

---

## Релиз 0.1 — каркас приложения

Сначала вообще никаких таблеток и воды.

Создаем:

```text
Vite
React
TypeScript
```

Подключаем:

```text
React Router
Zustand
React Hook Form
Zod
Dexie
date-fns
vite-plugin-pwa
```

Создаем layout:

```text

</AppLayout>
```

Маршруты:

```text

/settings
```

Получаем пустую аппку с работающим переключением экранов.

# Релиз 0.3 — первый рабочий функционал воды

Начинаем только с одной кнопки:

```text

```

Создаем store:

```ts
useWaterStore
```

```ts

  goal: 2500,
  entries: []
}
```

```ts

```

```text

```

↓

```text

```

Это первая полностью работающая фича.

# Релиз 0.5 — история воды

До этого мы могли хранить просто:

```ts
water: 1250
```

Теперь меняем структуру на нормальную:

```ts
waterEntries: [
  {
    id: "1",
    amount: 250,
    createdAt: "..."
  }
]
```

Теперь можно вычислять:

```ts
const todayWater = entries
  .filter(isToday)
  .reduce(...)
```

На `/water` выводим:

```text
Сегодня

08:10   250 мл
09:45   500 мл
11:30   250 мл
```

# Релиз 1.0

В итоге первая полноценная версия имеет:

```text
Сегодня
├── прогресс воды
├── добавить воду
└── прием таблеток

Таблетки
├── список
├── создать
├── изменить
├── удалить
├── расписание
└── несколько приемов

Вода
├── дневная цель
├── добавить
├── удалить запись
└── история

История
├── вода
└── таблетки

Настройки
├── цель воды
├── уведомления
└── тема

PWA
├── установка
├── offline
├── IndexedDB
└── notifications
```

## А состояние приложения в итоге я бы разделил так

```text
LOCAL STATE
│
├── открыта ли модалка
├── input
├── состояние формы
└── выбранная вкладка внутри компонента


GLOBAL STATE
│
├── medications
├── medicationIntakes
├── waterEntries
├── settings
└── пользовательские настройки


DERIVED STATE
│
├── сколько воды выпито сегодня
├── сколько осталось
├── препараты на сегодня
├── процент выполнения
└── статистика


PERSISTENT DATA
│
└── IndexedDB
```

И важный момент: **`todayWater`, `waterPercent`, `todayMedications` я бы не сохранял в store отдельно**. Их лучше вычислять из исходных данных. Иначе легко получить ситуацию, когда `waterEntries` обновились, а `todayWater` остался старым.

То есть архитектурно приложение получится достаточно взрослым, но при этом ты будешь собирать его постепенно: **сначала одна кнопка `+250 мл` → потом полноценный трекер воды → одна таблетка → расписание → история → IndexedDB → PWA → notifications → статистика**. Это хороший порядок для разработки pet-проекта.
